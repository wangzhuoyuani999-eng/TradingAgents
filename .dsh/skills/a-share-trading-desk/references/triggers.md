# 巡检触发条件与分档决策

## 一、巡检的推送判定（只在"需要注意"时才推飞书）

每轮先拉数据，再逐条判定。**满足任一条件才推飞书**，否则只在会话留一行极简摘要。

| 代号 | 触发条件 | 含义 |
|---|---|---|
| **A** | 持仓触及**止损位**或**目标位** | 必须动作 |
| **B** | 持仓相对成本偏离 **≥0.5%** 且方向不利，或单次巡检区间波动 **≥1%** | 异动 |
| **C** | 上证或创业板单日跌幅扩大到 **≥2%** | 系统性风险 |
| **D** | 情绪风向标股异动（如涨停打开、跌幅 >3%） | 板块情绪转折 |
| **E** | 出现需要用户下单的动作 | 直接给下单表 |
| **F** | **11:25 上午总结**、**14:50 收盘前总结** 各一次固定总结 | 不看条件，必推 |

**不推送时**会话里只留一行，格式固定：

```
HH:MM 无异常 海34.40
```

**推送时**必须包含：标题（时间 + 触发代号）、小表格（现价/涨跌/距成本/距止损）、两行判断。
内容要短——巡检是节奏性的，写长了跟不上。

## 二、非交易时段

- 09:30 前、11:30–13:00 午休、15:00 后：**只回「非交易时段，跳过」，不推飞书**。
  （例外：11:30 午盘复筛、12:00 午休尽调是**计划任务**，照跑，但不算巡检、不走本文件的格式。）
- 周末与节假日同上。

## 三、按价位分档的决策框架

巡检的核心不是报价，是**"到这个价位我该做什么"**。开仓前就要把档位写死，盘中只做匹配，不做临时判断。

### 持仓分档模板（以成本线 C、止损位 S、目标位 T 为界）

> **⚠️ 卖出必须整手（100 股为单位），不能减半。** 持仓只有 100 股时只有"全卖/全留"两个选项。
> 需要减仓时，用**止损上移**实现同等风险控制，并在输出里说明这一点。

| 现价区间 | 判定 | 动作 |
|---|---|---|
| **≥ T** | 到目标 | **全部卖出**；剩余止损上移到成本 |
| **T 与 C 之间** | 正常盈利 | 不动；止损保持 S |
| **C 附近（±0.5%）** | 保本线争夺 | 不动，盯收盘价 |
| **C 到 S 之间** | 由盈转亏 | 若当日多次测试 C 失败（≥3 次）→ 次日开盘全清 |
| **< S 且收盘确认** | 破位 | 次日开盘全清，不摊低成本 |
| **跳空 < S** | 跳空破位 | 开盘直接清，不等收盘 |

### 关键补充

- **"擦线"不等于"破位"**：收盘价距关键位 <0.55% 且当日支撑被反复测试未破 → 可再给一天观察，
  但**必须写明是最后一天**，次日无条件执行。
- **长假/周末前**要单独考虑：若已有浮亏且关键位岌岌可危，宁可**尾盘清仓**避免两天的隔夜敞口。
  这是对"收盘确认制"的**正当例外**，需在输出里说明理由。
- **反弹高度递减**是弱势特征：同一价位第 N 次测试时，若每次反弹高点都更低 → 倾向清。

## 四、买入侧的触发

候选池（`watchlist.json`）的每只标的必须带：`buyLow` / `buyHigh` / `condition` / `stopLoss` / `target`。

| 情形 | 动作 |
|---|---|
| 现价落在 `buyLow–buyHigh` 且缩量不破 MA20 | 可买（但仍受"一天一只"约束） |
| 现价高于 `buyHigh` | **不追**，等回踩 |
| 现价低于 `stopLoss` | **买点已失效**，重新评估，不接下跌 |
| 收盘突破位 ×1.002 且放量 | 追突破（次级方案） |

**买点失效后要给"重新入场条件"**，三条同时满足才考虑：

1. 收盘站回关键均线（如 MA10/MA20）
2. 成交量 ≥ 20 日均量 ×1.2
3. 大盘不弱（上证当日 ≥ -0.5%）

## 五、系统风险升级

| 信号 | 应对 |
|---|---|
| 上证跌破 MA200 | 停止开新仓（原规则） |
| **上证站回 MA20（收盘价）** | **允许开新仓（2026-11-27 替代解锁）**；解锁后首笔按试仓 1 手、单笔风险 ≤0.5% 执行，次日起转常仓 |
| 上证重新跌破 MA20（收盘） | 停止开新仓；已持仓按各自止损管理，不清仓 |
| 创业板单日 ≤ -3% | 提高推送频率，但**不因指数跌而砍个股** |
| 持仓逆势走强且跑赢指数 ≥5pp | 判定为真强势，可持有到目标 |

## 六、飞书推送（已落地，2026-11-24）

**没有 `feishu_push(...)` 这个工具**——那是旧文档的臆想。真实通道是 DSH-IM 的主动投递，用仓库脚本推：

```bash
# 触发才推；未触发不要推
./.venv/Scripts/python.exe tools/feishu_push.py --label 盘中巡检 --text "600428 触发 A：现价 10.41 ≤ 止损 10.45，收盘确认后明日清仓"
# 长文本用文件；纯文本加 --format plain
./.venv/Scripts/python.exe tools/feishu_push.py --label 收盘定池 --format markdown --text-file data/logs/pool.md
```

规则：

- **只要推送里有「要人动手」的内容（下单 / 撤单 / 改价 / 转账 / 确认成交），必须用 `--action` 参数**，它会把这些操作加粗成块放到消息**最上方**（`⚠️ 需要你操作`），正文只写背景与理由。多条操作传多个 `--action`。
  ```bash
  ./.venv/Scripts/python.exe tools/feishu_push.py --label 收盘总结 \
    --action "11-26 开盘卖 002415 海康 100 股（整手，市价）" \
    --action "11-26 开盘卖 600428 中远海特 100 股（整手，市价），余 200 股" \
    --text "两只均触发收盘确认制；明日不开新仓。"
  ```
  没有动作就不要传 `--action`，别为了好看滥用高亮。
- **只在触发（A–D）或到固定小结时点（11:25 / 14:55）推**；无异常一律不推，别把飞书刷成日志流。
- `label` 取值：`盘前分析` / `开盘指令` / `盘中巡检` / `上午总结` / `午盘复筛` / `午休尽调` / `收盘总结` / `收盘定池`。
- 一条 ≤ 3000 字符；飞书主动卡片**不会自动分段**，超长会被平台拒。
- 发送成功脚本打印 `sent:true`；失败打印错误码和处置建议（`bot-not-connected` 表示机器人离线，等恢复，不要连续重试）。
- **投递目标（2026-11-27 起）**：默认走**群**（`--to group`）；私有记账/复盘用 `--to private`（与本人私聊）；也可直接传 targetId。
- **机器人/目标 ID 不入库**：配在 `tools/.feishu_targets.json`（已被 .gitignore 忽略），或用环境变量 `FEISHU_BOT_ID` / `FEISHU_TARGET_GROUP` / `FEISHU_TARGET_PRIVATE` 覆盖；缺配置时脚本会明确报错并给提示。
- 不要再写「推飞书」而不真调用脚本——**写完必须实际执行一次**，看输出是不是 `sent:true`。
